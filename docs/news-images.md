# Фотография новости

Новости поддерживают одну фотографию: загрузку файла JPG/JPEG, PNG или WebP,
замену и удаление. Поле `image` в JSON содержит адрес изображения. Внешние ссылки
по-прежнему можно передавать через существующие методы создания и изменения
новости. Изменения схемы БД и новые зависимости не требуются.

## API

Пути указаны относительно API. При `--root-path /api` добавляется префикс `/api`.
Загрузка и удаление доступны только администратору с cookie `access_token`.
Просмотр фотографий публичный, как и просмотр самих новостей.

| Метод | Назначение |
| --- | --- |
| `POST /news/{news_id}/image` | Загрузить или заменить фото: `multipart/form-data`, поле `image` |
| `DELETE /news/{news_id}/image` | Удалить фото; повторное удаление также успешно |
| `GET /media/news/{filename}` | Получить загруженное фото |

POST и DELETE возвращают `200` и полную новость (`NewsResponse`). После загрузки
`image` содержит путь вида `/api/media/news/<news-id>_<random-id>.webp`, после
удаления — `null`. Получение новости и списка новостей возвращает тот же адрес.
В БД сохраняется путь без `root_path`; обратная передача адреса в JSON PUT
не дублирует префикс. Внешние и старые ссылки сохраняются без преобразования.
Абсолютные ссылки на этот же API нормализуются в локальный путь. Query-параметры
и фрагменты сохраняются и не считаются заменой файла; последующее удаление или
замена фотографии корректно очищает файл и для таких ссылок.

При создании сначала выполните `POST /news/`, затем загрузите фотографию
по полученному `id`. Если файл загрузить не удалось, новость остаётся доступной,
а загрузку можно повторить.

```javascript
// apiBase, например, "https://psychohelp-mospoly.ru/api".
async function uploadNewsPhoto(apiBase, newsId, file) {
  const form = new FormData();
  form.append("image", file);
  const response = await fetch(`${apiBase}/news/${newsId}/image`, {
    method: "POST",
    credentials: "include",
    body: form,
  });
  // Content-Type задаёт браузер: заголовок должен содержать multipart boundary.
  const result = await response.json();
  if (!response.ok) throw new Error(result.detail || "Не удалось загрузить фото");
  return result;
}
```

```bash
curl -b cookies.txt -F 'image=@photo.jpg' \
  http://localhost:8000/news/NEWS_UUID/image
```

## Форматы и ограничения

- JPG/JPEG (`image/jpeg`), PNG (`image/png`), WebP (`image/webp`), до **10 МиБ**.
- До **20 млн пикселей**, не более **10 000 пикселей** по любой стороне.
- Проверяются MIME, фактический формат и декодирование. Пустые, повреждённые,
  анимированные изображения и остальные форматы отклоняются.
- EXIF-ориентация применяется; метаданные удаляются. Результат сохраняется в WebP.
- Исходное имя файла не используется. Публичный маршрут принимает только
  сгенерированные имена, отклоняет символьные ссылки и отдаёт `nosniff`.
- Поток запроса ограничен до multipart-разбора: 10 МиБ + 64 КиБ на служебные
  данные, включая запросы без `Content-Length` или с заниженным значением.

| Код | Причина |
| --- | --- |
| 400 | Пустой/повреждённый файл, неверный MIME, анимация, слишком большое разрешение или некорректный Content-Length |
| 401 / 403 | Нет авторизации / роли администратора |
| 404 | Новость или файл не найдены |
| 413 | Превышен размер файла или всего запроса |
| 415 | Неподдерживаемый формат |
| 422 | Некорректный UUID или отсутствует поле `image` |
| 500 | Ошибка записи файла или БД |

## Хранение и выпуск

Файлы хранятся в `${IMAGE_DIR}/news`, каталог создаётся при первой загрузке.
Docker Compose уже сохраняет `${IMAGE_DIR}` в томе; процессу нужны права на запись.
Reverse proxy должен пропускать `/api/media/news/` в API и разрешать запросы
больше 10 МиБ с учётом формы, например `client_max_body_size 11m` для nginx.

Запись файла атомарная; обработка изображения выполняется вне цикла событий API.
При ошибке сохранения в БД новый файл удаляется, старая фотография сохраняется.
Строка новости блокируется при изменении и удалении, чтобы одновременные замены
корректно определяли предыдущий файл.

После успешной замены, очистки `image` через JSON/DELETE или удаления новости
предыдущий загруженный файл удаляется. Внешние ссылки и файлы других новостей
не удаляются. Загруженная фотография принадлежит одной новости; для другой
новости загрузите отдельную копию. Ошибки очистки журналируются.

## Проверка

```bash
uv run --extra dev pytest tests/test_news_images.py tests/test_article_images.py \
  tests/test_partial_updates.py tests/test_images.py tests/test_openapi_contract.py

TEST_DATABASE_URL=postgresql+asyncpg://user:password@localhost/test_db \
  uv run --extra dev pytest tests/test_news_images_postgres.py
```

PostgreSQL-тесты создают отдельную схему и удаляют её после проверки. Они проверяют
сохранение в БД, одновременные замены, откат транзакции и удаление во время загрузки.
