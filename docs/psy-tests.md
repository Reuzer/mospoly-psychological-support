# Психологические тесты

Список и карточка теста доступны через `GET /psy-tests/` и `GET /psy-tests/{id}`.
Защищённые операции используют cookie `access_token`. Пути в примерах указаны
относительно API.

## Создание и вопросы

`POST /psy-tests/` возвращает `201`. У развлекательного теста обязателен
внешний `url` с протоколом HTTP или HTTPS. В базе хранится ссылка, прохождение
происходит на внешнем сайте. Для управления каталогом развлекательных тестов
действуют права `tests.create`, `tests.edit` и `tests.delete`.

Медицинские тесты создают психологи и администраторы. В одном тесте можно
сочетать вопросы с текстовым ответом, одиночным и множественным выбором.
Порядок прохождения задаёт массив `questions`.

```json
{
  "title": "Самочувствие",
  "description": "Короткий опрос о самочувствии",
  "type": "Медицинский",
  "questions": [
    {"text": "Как вы спали?"},
    {
      "type": "single_choice",
      "text": "Какое у вас настроение?",
      "options": [{"text": "Спокойное"}, {"text": "Тревожное"}]
    },
    {
      "type": "multiple_choice",
      "text": "Что помогло вам отдохнуть?",
      "options": [{"text": "Сон"}, {"text": "Прогулка"}, {"text": "Общение"}]
    }
  ]
}
```

В медицинском тесте доступно от 1 до 100 вопросов. Сервер присваивает каждому
вопросу UUID и позицию, начиная с 1. У вопроса с типом `text` список вариантов
пустой. Поле `type` можно опустить для текстового вопроса. Для `single_choice` и
`multiple_choice` требуется от 2 до 100 вариантов. Сервер присваивает каждому
варианту UUID и возвращает варианты в заданном порядке.

Внешний `url` доступен для развлекательных тестов. Тип теста фиксируется при
создании.

| Метод и путь | Действие психолога или администратора |
| --- | --- |
| `GET /psy-tests/{id}/questions` | Получить вопросы с полями `id`, `position`, `text`, `image`, `type` и `options` в порядке прохождения. У каждого варианта есть `id` и `text` |
| `PUT /psy-tests/{id}/questions` | Заменить список в теле `{"questions": [...]}`. Сервер создаёт новые UUID и удаляет прежние изображения |
| `POST /psy-tests/{id}/questions/{question_id}/image` | Загрузить изображение в multipart-поле `image`. Поддерживаются JPEG, PNG и WebP до 10 МБ |
| `DELETE /psy-tests/{id}/questions/{question_id}/image` | Очистить изображение вопроса |

До загрузки изображения `image` равен `null`. После старта первого прохождения
вопросы, варианты и изображения фиксируются. Попытка обновить их
возвращает `409`. Для прежних медицинских тестов вопросы можно добавить через
`PUT /psy-tests/{id}/questions`. Прежним развлекательным тестам ссылку можно
добавить через `PUT /psy-tests/{id}`.

## Прохождение студентом

| Метод и путь | Действие |
| --- | --- |
| `POST /psy-tests/{id}/attempts` | Начать прохождение или получить уже начатое. После завершения вызов создаёт новое прохождение |
| `GET /psy-tests/{id}/attempts/{attempt_id}` | Получить собственные сохранённые ответы и следующий вопрос |
| `PUT /psy-tests/{id}/attempts/{attempt_id}/answers/{question_id}` | Сохранить один ответ на вопрос из `next_question` |

Формат тела запроса зависит от типа вопроса.

| Тип вопроса | Тело запроса |
| --- | --- |
| `text` | `{"answer":"Спал хорошо"}` |
| `single_choice` | `{"option_ids":["<uuid варианта>"]}` |
| `multiple_choice` | `{"option_ids":["<uuid первого варианта>","<uuid второго варианта>"]}` |

Для одиночного выбора нужен ровно один UUID, для множественного — один или
несколько. Принимаются уникальные UUID из `next_question.options[].id`.
Неверный формат, пустой выбор, дубликаты и варианты другого вопроса возвращают
`422`. Сохранённый ответ содержит `answer` для текста или `option_ids` для
выбора. Выбранные UUID возвращаются в порядке вариантов вопроса.

Сервер возвращает `200`, идентификатор прохождения, `answers` с вопросами,
ответами и временем сохранения, `completed_at` и `next_question`. У клиента
может быть одна активная попытка на тест. Повторный старт позволяет продолжить
её с другого устройства.

Повторная отправка того же ответа возвращает текущий прогресс. Порядок UUID
в запросе не влияет на сравнение выбранных вариантов. Изменение сохранённого
ответа или пропуск вопроса возвращает `409`. Последний ответ
устанавливает `completed_at` и возвращает `next_question: null`. Правильные
ответы и оценивание не предусмотрены.

## Просмотр ответов и счётчик

| Метод и путь | Действие психолога |
| --- | --- |
| `GET /medical-records/{user_id}/test-attempts?skip=0&take=100` | Получить список завершённых и незавершённых прохождений |
| `GET /medical-records/{user_id}/test-attempts/{attempt_id}` | Получить вопросы и сохранённые ответы конкретного прохождения |

Просмотр ответов других пользователей доступен роли психолога. Студент
получает свои ответы через собственное прохождение.

Сохранение последнего ответа и запись в `psy_test_completions` выполняются в
одной транзакции. Медкарта считает уникальные ID завершённых медицинских тестов.
Незавершённое прохождение счётчик не увеличивает. Удаление медицинского теста
архивирует его, скрывает из каталога и сохраняет историю. Начатое до архивации
прохождение можно закончить.
