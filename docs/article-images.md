# Фотография статьи

## Архитектура

Проект — backend на FastAPI. Контроллеры в `psychohelp/routes/controllers` принимают
запросы и проверяют права, `services` содержит бизнес-логику, `repositories` работает
с PostgreSQL через асинхронные сессии SQLAlchemy. Pydantic-схемы определяют API,
Alembic управляет схемой базы. Роли и права проверяются существующим RBAC.
Фронтенда в этом репозитории нет.

У статьи уже есть nullable-поле `image` (`String(1024)`); оно используется для ссылки
на одну фотографию. Новая миграция и новые зависимости не требуются: Pillow и
python-multipart уже входят в проект. Существующие JSON-методы создания и
редактирования статьи сохраняются, включая ссылки в `image` и очистку через `null`.

Обработка файлов находится в `services/article_images.py`. Сервис статей
координирует сохранение файла и изменение БД. Изменения и удаление статьи блокируют
её строку через `SELECT FOR UPDATE`, чтобы параллельные замены корректно определяли
предыдущую фотографию. Контроллер изображений публично отдаёт готовые WebP-файлы.

## API

Все пути ниже указаны относительно API. На стенде с `--root-path /api` добавляется
префикс `/api`. Для изменения фотографии нужна cookie `access_token` и право
`articles.edit`; наличие только `articles.create` или `articles.delete` его не заменяет.

| Метод и путь | Действие |
| --- | --- |
| `POST /articles/{article_id}/image` | Загрузить или заменить фото; `multipart/form-data`, поле `image` |
| `DELETE /articles/{article_id}/image` | Удалить фото; повторное удаление тоже возвращает успех |
| `GET /media/articles/{filename}` | Публично получить загруженное фото |

POST и DELETE возвращают `200` и полную статью (`ArticleResponse`), включая `image`.
После удаления `image` равен `null`. Список статей и отдельная статья также
возвращают ссылку. Для загруженных фото ссылка учитывает `root_path`, например
`/api/media/articles/<article-id>_<random-id>.webp`; в БД хранится путь без префикса.
Внешние и старые ссылки сохраняются без преобразования. Возвращённую ссылку можно
отправить обратно в JSON PUT: она нормализуется и не получает двойной префикс.
Абсолютные ссылки на этот же API также нормализуются в локальный путь.
Query-параметры и фрагменты сохраняются и не считаются заменой файла;
последующая замена или удаление фотографии корректно очищает такой файл.

Статья должна существовать: при создании сначала выполните обычный
`POST /articles/`, затем загрузите файл по полученному `id`. Если загрузка не удалась,
созданная статья остаётся доступной, загрузку можно повторить.

```javascript
// apiBase, например, "https://psychohelp-mospoly.ru/api".
async function uploadArticlePhoto(apiBase, articleId, file) {
    const form = new FormData();
    form.append("image", file);

    const response = await fetch(`${apiBase}/articles/${articleId}/image`, {
        method: "POST",
        credentials: "include",
        body: form,
    });
    // Content-Type вручную не задаётся: браузер добавит multipart boundary.
    const result = await response.json();
    if (!response.ok) throw new Error(result.detail || "Не удалось загрузить фото");
    return result;
}
```

Пример загрузки локально с cookie, полученной при входе:

```bash
curl -b cookies.txt -F 'image=@photo.jpg' \
  http://localhost:8000/articles/ARTICLE_UUID/image
```

## Валидация и ошибки

- Допускаются JPEG, PNG и WebP, до **10 МиБ**, до **20 000 000 пикселей**,
  не более **10 000 пикселей** по любой стороне. Анимация отклоняется.
- Проверяются заявленный MIME, фактический формат и возможность декодирования.
  SVG, произвольные файлы и повреждённые изображения не сохраняются.
- EXIF-ориентация применяется к пикселям; метаданные и дописанные к исходному файлу
  данные удаляются. Публичный файл заново кодируется в WebP.
- Исходное имя файла не используется. Публичный маршрут принимает только имена,
  сгенерированные сервером, отклоняет символьные ссылки и отдаёт `nosniff`.
- До multipart-разбора ограничен весь поток запроса: 10 МиБ + 64 КиБ на заголовки
  и границы формы. Проверяется реальный объём, включая запросы без Content-Length
  или с заниженным значением. Чтение самого файла также ограничено 10 МиБ + 1 байт.
- Декодирование и запись выполняются в рабочем потоке, вне цикла событий API.

| Код | Причина |
| --- | --- |
| 400 | Пустой/повреждённый файл, несоответствие MIME, анимация, превышение разрешения или неверный Content-Length |
| 401 / 403 | Нет авторизации / права `articles.edit` |
| 404 | Статья или публичный файл не найдены |
| 413 | Превышен размер файла или всего запроса |
| 415 | Неподдерживаемый тип изображения |
| 422 | Некорректный UUID или отсутствует поле `image` |
| 500 | Ошибка записи файла или БД |

## Хранение и выпуск

Файлы находятся в `${IMAGE_DIR}/articles`; каталог создаётся при первой загрузке.
В Docker используется существующий том изображений. Процессу приложения нужны права
на запись. Для reverse proxy необходимо разрешить multipart-запросы размером
больше 10 МиБ с учётом служебных данных формы, например `client_max_body_size 11m`
в nginx, и проксировать `/api/media/articles/` в API вместе с другими API-маршрутами.

Новый файл сначала полностью записывается во временный файл и атомарно переименовывается.
Ссылка меняется в транзакции БД. При ошибке транзакции новый файл удаляется,
предыдущая ссылка и файл сохраняются. Если статью удалили во время обработки,
новый файл очищается, клиент получает 404.

После успешной замены, очистки `image` через JSON/DELETE или удаления статьи
удаляется прежний загруженный файл этой статьи. Старые/внешние ссылки и файлы с
идентификатором другой статьи не удаляются. Загруженная фотография принадлежит
статье: для другой статьи загружайте отдельную копию. Ошибки очистки
файлов журналируются и не отменяют уже сохранённое изменение БД. При аварийном
завершении процесса между записью файла и коммитом возможны неиспользуемые файлы;
при обслуживании хранилища их следует сверять с актуальными ссылками в БД.

Текущий контракт экспортирован в `swagger.yaml` командой
`python scripts/export_openapi.py`.

## Проверки

```bash
uv run --extra dev pytest tests/test_article_images.py tests/test_articles.py \
  tests/test_partial_updates.py tests/test_images.py tests/test_openapi_contract.py

# Только отдельная тестовая PostgreSQL: тесты создают и удаляют собственные схемы.
TEST_DATABASE_URL=postgresql+asyncpg://user:password@localhost/test_database \
  uv run --extra dev pytest tests/test_article_images_postgres.py
```

Проверяются полный цикл загрузки/замены/удаления, чтение в списке и карточке,
работа за `/api`, права, ограничения потока, валидация изображений, удаление EXIF,
обход путей, сбои диска и БД. PostgreSQL-тесты дополнительно проверяют сохранение,
откат реальной транзакции, конкурентные замены и удаление во время обработки.
