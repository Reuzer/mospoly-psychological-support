# Экстренный контакт записи

`PATCH /appointments/{id}/emergency-contact` изменяет поле `emergency_contact`.
Авторизация — cookie `access_token`. Доступ имеют студент этой записи и назначенный
психолог (сравнивается `psychologist.user_id`). Роль администратора не даёт обхода
этой проверки.

```json
{"emergency_contact": "Анна, мама, +79991234567"}
```

Поле обязательно в теле запроса; допускается строка или `null`. Пробелы по краям
удаляются, пустая строка становится `null`. Максимальная длина после обрезки —
512 символов. Лишние поля запрещены. Для очистки отправьте:

```json
{"emergency_contact": null}
```

Изменение разрешено только в статусе `awaiting`, независимо от даты консультации.
После завершения или отмены контакт сохраняется для чтения участниками.
Ответ `200` содержит обновлённую запись; поле также возвращается в
`GET /appointments/` и `GET /appointments/{id}`. В ответах API заявок поле отсутствует.
При создании записи контакт по умолчанию равен `null`; заполнение — отдельным PATCH.

Ошибки: `401` без авторизации, `404` для отсутствующей или чужой записи,
`409` для неактивной записи, `422` для неверного UUID или тела запроса.
Сохранение обновляет `last_change_time` в UTC. Проверка статуса и изменение
выполняются под блокировкой строки в одной транзакции. При одновременном изменении
контакта сохраняется последнее успешно записанное значение.

## Выпуск и проверка

Сначала применить `alembic upgrade head`, затем развернуть backend. Миграция
`f3a4b5c6d7e8` добавляет nullable-колонку; существующие записи получают `NULL`.
Откат этой миграции удаляет колонку вместе с сохранёнными контактами.

Модульные и HTTP-тесты: `python -m pytest tests/test_appointment_emergency_contact.py`.
PostgreSQL-тесты: задать `TEST_DATABASE_URL` в формате
`postgresql+asyncpg://user:password@localhost:port/database` и запустить
`python -m pytest tests/test_appointment_emergency_contact_postgres.py`.
Эти тесты создают и удаляют собственные изолированные схемы в указанной БД.
Без `TEST_DATABASE_URL` PostgreSQL-тесты пропускаются.
