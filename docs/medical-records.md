# Медкарты пациентов

Авторизация — cookie `access_token`. Все методы доступны психологам и
администраторам. Неавторизованный запрос получает `401`, пользователь без этих
ролей — `403`, в том числе при обращении к собственной медкарте.

Карточка существует для каждого пользователя с ролью `user`, даже если у него
ещё не было приёмов. Дополнительные роли не создают дубликатов и не исключают
карточку из списка. Отдельного признака студента в текущей модели нет.
Идентификатор карточки `id` совпадает с `user.id`; при смене психолога он не
меняется. Чтение не создаёт дополнительных записей в базе.

## Превью

`GET /medical-records/` → `200`, массив `MedicalRecordPreview`:

```json
{
  "id": "UUID пользователя",
  "user": {"...": "полный UserResponse, как в профиле"},
  "note": null
}
```

Список возвращается целиком, без пагинации и серверной сортировки. Если
пользователей с ролью `user` нет, ответ — `[]`.

Номер телефона в `UserResponse` приводится к формату E.164. Если в профиле
сохранился некорректный номер, в ответах профиля и медкарты `phone_number`
равен `null` до обновления номера. Обновление с некорректным номером возвращает
`422` до записи в БД.

## Медкарта

`GET /medical-records/{user_id}` → `200`, `MedicalRecordResponse`:

| Поле | Содержимое |
| --- | --- |
| `id` | UUID пользователя, совпадает с ID карточки в превью |
| `user` | Полный `UserResponse`, включая роли, контакты и учебную группу |
| `note` | Общая для всех психологов заметка, изначально `null` |
| `note_version` | Неотрицательная версия заметки, изначально `0` |
| `next_appointment` | Ближайший будущий приём `awaiting` или `null` |
| `completed_appointments` | Все приёмы пациента в статусе `done` или `[]` |
| `tests_count` | Количество уникальных пройденных медицинских тестов |
| `surveys_count` | Количество уникальных пройденных опросов |

Будущим считается приём с `scheduled_time` строго больше текущего времени UTC.
При равном времени выбирается наименьший UUID приёма. Прошедшие `awaiting` и
отменённые приёмы не выбираются. Завершённые приёмы возвращаются без сортировки,
пагинации и ограничения количества, независимо от назначенного психолога.

`MedicalAppointment` содержит поля существующего `AppointmentBase` и дополнительно
`psychologist_comment` — внутренний комментарий психологам. В общую схему
`AppointmentBase` это поле не добавляется. Заметка пациента и её версия также
не включаются в `UserResponse`, вложенные профили приёмов, ответы входа,
регистрации и обновления профиля. Изменение обычного профиля не меняет заметку.

Отсутствующий пользователь или пользователь без роли `user` получает `404`.
Некорректный UUID — `422`.

## Сохранение заметки

`PATCH /medical-records/{user_id}/note`:

```json
{"note": "Заметка для психологов", "note_version": 0}
```

Оба поля обязательны. `note` — строка или `null`; `note_version` — целое число
не меньше нуля без преобразования строк, дробей и логических значений.
Посторонние поля запрещены. Текст сохраняется без обрезки; пустая строка допустима.
Для очистки передайте `null` и последнюю полученную версию.

Ответ `200`:

```json
{"note": "Заметка для психологов", "note_version": 1}
```

Каждое успешное сохранение, включая очистку и сохранение прежнего текста,
увеличивает версию на единицу. Проверка версии и запись выполняются под
блокировкой строки в одной транзакции. Если другой специалист уже изменил
заметку, сервер возвращает `409`, не меняя текст и версию. Клиенту нужно
повторно прочитать медкарту и предложить пользователю согласовать правку.
Отсутствующая медкарта — `404`, неверное тело запроса — `422`.

## Источники счётчиков

Счётчики читают таблицы завершённых прохождений:

- `psy_test_completions`: `id`, `user_id`, `test_id`, `completed_at`;
- `survey_completions`: `id`, `user_id`, `survey_id`, `completed_at`.

Каждая строка означает завершённое прохождение. Счётчики используют
`COUNT(DISTINCT test_id)` и `COUNT(DISTINCT survey_id)` для конкретного пользователя.
В `tests_count` учитываются тесты типа `MEDICAL`. Запись о прохождении создаётся
вместе с последним ответом. Архивация теста сохраняет историю и счётчик.
При удалении пользователя удаляются его прохождения.

Психологи могут открыть вопросы и ответы студента через API результатов.
Маршруты и формат ответов описаны в [API психологических тестов](psy-tests.md).
Для опросов пока требуется источник записей в `survey_completions`. При
отсутствии записей `surveys_count` равен `0`.

## Выпуск и проверка

Перед запуском обновлённого backend применить `alembic upgrade head`.
Ревизия `f7a8b9c0d1e2` объединяет миграции медкарт и синхронизации аватаров.
Миграция `a6b7c8d9e0f1` добавляет `users.note`, `users.note_version`, ограничение
неотрицательной версии, таблицы прохождений и индекс поиска приёмов пациента.
Существующие пользователи получают `note = NULL`, `note_version = 0`.
Откат удаляет заметки, версии и историю прохождений, сохраняя пользователей и приёмы.

HTTP-проверки:

```bash
python -m pytest tests/test_medical_records.py
```

Проверки реальных запросов, конкурирующих правок и миграции в PostgreSQL:

```bash
TEST_DATABASE_URL=postgresql+asyncpg://user:password@localhost:port/database \
  python -m pytest tests/test_medical_records_postgres.py
```

PostgreSQL-тесты создают и удаляют собственные временные схемы в указанной БД.
Без `TEST_DATABASE_URL` эти проверки пропускаются.
